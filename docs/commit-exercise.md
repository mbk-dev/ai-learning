# Проверка скилла commit

Используйте отдельный учебный репозиторий без рабочих секретов.
Для проверки push/PR выбирайте специально предназначенный учебный remote.

## Локальный коммит

1. Подготовьте воспроизводимую ошибку и её исправление с содержательным тестом.
2. Добавьте отдельную правку, не связанную с исправлением, и заранее сохраните
   её содержимое для сравнения.
3. Попросите агента применить `commit` и создать только локальный коммит исправления.
4. Проверьте фактическую дельту созданного коммита и состояние рабочего дерева.

Ожидаемый результат:

- Проверки проекта выполнены до коммита.
- В коммит вошли только изменения исправления.
- Посторонняя правка сохранилась без изменений.
- Push и PR не выполнялись.
- Агент сообщил SHA, сообщение коммита и результаты проверок.

## Разрешение в предыдущем сообщении

Поручите агенту сделать локальный коммит после исправления, а затем уточните
деталь исправления отдельным сообщением. Действующее разрешение должно
сохраниться в рамках задачи; повторный запрос разрешения на тот же commit не нужен.

## Общий индекс

В отдельном опыте добавьте постороннюю правку в staging area до запуска агента.
Он должен распознать её, не включать в свой коммит и не сбрасывать чужой stage.
Если строки смешаны в одном файле, одного выбора имени файла недостаточно.

## Push и PR

Отдельно разрешите push и PR. Проверьте целевые remote/head/base, состав
отправляемой истории и отсутствие второго PR для той же задачи. Ручные материалы
описания существующего PR и его draft/ready должны сохраниться.

Это сценарии приёмки для слушателей, а не отчёт о пройденных экспериментах.
