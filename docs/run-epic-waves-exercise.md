# Практика: выполнение задач волнами по графу

Материал для дней 2–3 [курса, веха 1](https://github.com/mbk-dev/presentations/milestone/1).
Цель — научиться выбирать независимые задачи, ограничивать исполнителей,
проверять результат и интегрировать каждую волну.

## Подготовка

Используй отдельный учебный репозиторий с Git и доступными командами проверок.
Установи `course-run-epic-waves` по README набора, проверь его доступность в новой
сессии. Для Codex настрой [нативные роли](codex-native-subagents.md).
Доступов к Aqualibrium, внешних API-ключей и production-сервисов не требуется.
Два исполнителя и один read-only ревьюер достаточны для примера; сверь фактический
лимит аккаунта. Если делегирования нет, сначала выполни планирование последовательно
и отдельно отметь, что параллельный прогон не проводился.

Преподаватель задаёт права: например, локальные правки/commit разрешены,
push/merge — только в явно выбранный учебный репозиторий. Это пример границ,
а не предоставление прав на какой-либо существующий репозиторий.

## Запрос агенту

> Используй course-run-epic-waves для упражнения CLI с CSV из примера скилла.
> Сначала проверь инструкции и реальные возможности среды, зафиксируй граф,
> критерии, выбранные язык и команды проверок, права и учебные пределы.
> Выполняй независимые задачи волнами, проверяй работу исполнителей и интеграцию.
> После доставки каждой волны пересчитывай граф. Не повторяй неизвестные операции.
> Сохрани запись волн с доказательствами и раздельный итог реализации и доставки.

[Контракт задачи, графы и сценарии ошибок](../skills/course-run-epic-waves/references/example.md).
Вводное задание: до запуска объяснить, почему B/C можно выполнять одновременно,
а D нельзя, и кто имеет право менять общие файлы.

## Что сдаёт участник

- Граф A → B/C → D и проверяемый DoD с точными путями/интерфейсами.
- Брифы и запись трёх волн: владельцы, worktree, handles, счётчики и evidence.
- Реальные diff, результаты проверок и интеграции, target SHA при разрешённой доставке.
- Разбор одного сценария ошибки из примера с сохранением ограничений и владения.
- Краткий итог с явными непроведёнными проверками и pending, если они остались.

Преподаватель проверяет артефакты, а не только рассказ агента. «Готово» без
проверок, D до доставки B/C, общий writer или слепой повтор push — ошибки приёмки.
Без прав на merge допустим проверенный промежуточный результат с точным запросом;
он не считается завершённой доставленной волной.

## Статус проверки материала

Пример и сценарии предназначены для учебного прогона. Проверка структуры файлов,
ссылок и схем не доказывает поведение агента или воспроизводимость на чистой VM.
Результаты реального занятия нужно сохранить отдельно с датой и параметрами среды.

Проверки пакета 15.11.2026: `quick_validate.py` — PASS; совместимость с
AGENTS.md учебного репозитория — PASS; 20 локальных ссылок в изменённых материалах
ведут к существующим файлам; Skills CLI обнаружил все 4 скилла, включая новый.
Граф поведения прошёл штатный `graph_check.py`; оба графа отрисованы Mermaid CLI
11.17.1 и просмотрены. Прогон агентов и установка на чистой VM не проводились.
